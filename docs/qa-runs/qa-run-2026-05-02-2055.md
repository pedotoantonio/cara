## Issue irrisolte

### IRR.1 — Definitions hallucination (D.2)

**Sintomo:** "Cos'è la fusione fredda?" → genera definizione inventata invece di emettere `[TOOL: discover ...]`. Replicato anche dopo aver aggiunto few-shot diretti.

**Diagnosi:** il 1.5B "riconosce" il termine come parte della propria training data e compone una pseudo-definizione plausibile sbagliata. Le few-shot non bastano a sovrascrivere quel comportamento — è la firma del modello, non un bug del prompt.

**Fix proposto per la prossima iterazione:** implementare l'**agent loop**:
1. Server detecta `[TOOL: discover ...]` nel buffer durante streaming OR genera senza tool
2. Per intent di tipo "definizione/spiegazione/cosa-è" forza il discover anche se il LLM non l'ha emesso
3. Esegui discover server-side, riceve l'articolo
4. Lancia un secondo round LLM con l'articolo nel prompt + istruzione "riassumi in 2-3 frasi"
5. Streama il secondo round come continuazione SSE

Oppure (più semplice): aggiunge un classificatore lightweight (regex su keywords "cos'è|spiegami|definisci|chi è") che forza un `[TOOL: discover ...]` server-side prima della prima inferenza, e fornisce il risultato già nel prompt iniziale. Costa zero al modello (zero ulteriori token generati).

### IRR.2 — Latenza cronica alta

**Sintomo:** TTFT 14-20 s, 0.2-3 tok/s. Sotto soglia (target ≤ 8 s, ≥ 9 tok/s).

**Diagnosi:** frigate object detection occupa il NPU via `/dev/dri/card0` (single-tenant). Confermato in CLAUDE.md Step 16 — il throughput baseline 9 tok/s scende a 1-3 tok/s sotto carico frigate.

**Fix non applicato** (fuori scope per QA prompt-tuning):
- Limitare frigate (cap CPU, throttle detection ai motion event)
- Rotazione: pause frigate quando CARA è in chat
- Upgrade hardware (NPU dedicato)
